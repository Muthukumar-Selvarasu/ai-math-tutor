## Story Statement
**As a** student, **I want** to see a full worked solution only after meaningful effort or configured support steps, **so that** I learn the method instead of copying the answer.

### Acceptance Criteria (Given / When / Then)
- [x] **Given** the student presses "Show me the solution" (the only Level 5 request) before all level 5 conditions in PRD section 22.1 (#19) are met, **when** policy runs, **then** the tutor gives the next permitted hint and does not reveal the final answer. Submissions of "I am not sure" do not count toward the 3-attempt requirement.
- [x] **Given** the original item is at hint level 4, the student has at least 3 counted substantive attempts, the student asks for the solution, and `allow_level_5` is true (opted-in by coordinator or demo config), **when** policy runs, **then** a worked solution is shown and a transfer question follows. Any missing condition keeps the next permitted hint. A transfer item does not receive a worked solution.
- [x] **Given** those conditions hold except `allow_level_5` is false (default), **when** the student asks, **then** the tutor provides structured fallback (an isomorphic worked example with different numbers or Level 4 template), notifies the student that this question has been saved for their teacher, and records `support_withheld`.
- [x] **Given** a solution is shown, **when** the audit row is written, **then** it records hint level, attempt count, and policy version.
- [x] **Given** a prompt-injection attempt to bypass policy, **when** it is screened, **then** the request is blocked and logged as a safety event.
- [x] **Given** a candidate turn generated by the dialogue agent, **when** evaluated, **then** the deterministic leakage check runs first inside the loop. A match against blocked solution steps or final answer triggers loop revision. Digit-rule exemptions below Level 4 are exactly three: values quoted verbatim from the question stem, values quoted verbatim from the selected authored probe template, and the student's own value that the verifier marked correct this attempt. The value-leak check also exempts probe expected values already produced (answered) in this session; probe values not yet produced, including the selected probe's own expected value, stay forbidden and are sent to the guard. If revisions exhaust, the deterministic fallback prompt is returned.
- [x] **Given** all four Level 5 conditions hold and the student presses "Show me the solution", **when** the turn runs, **then** the solution is rendered from the item's authored steps by the deterministic template with no model and no guard call (`tutor.kind=solution`), the canned `transfer_offer` follows in the same text, and the session moves to `transfer_offered`.
- [x] **Given** the other conditions hold but `allow_level_5` is false, **when** the student presses "Show me the solution", **then** the turn is rendered from the item's isomorphic example followed by the canned `support_withheld_notice` (`tutor.kind=authored`), `support_withheld` is recorded, the state stays `active`, and the item's own answer is not shown.
- [x] **Given** the student presses "Show me the solution" while any other condition is unmet, **then** the level is unchanged, the next unused probe at the current level is paraphrased through the normal loop (or the canned `encouragement` is sent when none is left, with no model call), and the request is audited.
- [x] **Given** the Safety Guard returns allow on a candidate that contains a blocked solution value, **when** the turn is about to be stored, **then** the deterministic leakage check still blocks it (a hit overrides allow). The student's own value is exempt when the verifier has already marked that same value correct on this attempt (read from the current attempt's `verifier_outcome` in ADK state, applied inside `check_candidate` only).

### Implementation Log & Technical Notes
- `2026-10-12`: Initial issue initialized in local tracker as per task-manager.
- `2026-10-12`: Implemented `lib/input-screen.js` providing deterministic input screening (PRD §8.3.1, AG-01) for prompt injection, abuse, assessment help, impersonation, worrying disclosure, and direct answer requests.
- `2026-10-12`: Implemented `lib/leak-checker.js` providing deterministic leakage verification (AG-09, SPEC WF-09), enforcing final answer leakage, intermediate step leakage, method leakage, single-prompt structure, and digit-rule exemptions (verbatim question stem, verbatim probe template, verified student values, produced probe values).
- `2026-10-12`: Updated `lib/session-store.js` to implement Level 5 solution gating:
  - 4 gating conditions: (a) Level 4, (b) >= 3 counted substantive attempts, (c) button clicked, (d) `allow_level_5` flag.
  - Branch 1 (all 4 met): `kind=solution`, deterministic solution template + `transfer_offer`, transition to `transfer_offered`, audit `solution_revealed`.
  - Branch 2 (a-c met, `allow_level_5=false`): `kind=authored`, isomorphic worked example + `support_withheld_notice`, flag `support_withheld`, state stays `active`.
  - Branch 3 (any unmet): level unchanged, next probe or `encouragement`, audit `solution_request_denied`.
  - Added transfer response handling: `accept` transitions to `transfer_active` at Level 0; `decline` transitions to `declined`.
  - Integrated candidate leak check with Safety Guard override (deterministic leak hit blocks candidate and falls back to `fallback_l{hint_level}`).
  - Added Input Screen check for prompt injection and abuse on answers and notes.
- `2026-10-12`: Updated `app/practice/page.jsx` UI with `allowLevel5` coordinator toggle, Show Solution action handler, and Transfer question accept/decline action buttons.
- `2026-10-12`: Created Playwright test suite `tests/e2e/stu-05-summary-and-remediation.spec.ts` covering all 10 acceptance criteria.
